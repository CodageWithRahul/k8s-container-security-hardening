The official image's bundled configuration directories include cis-1.12 but

Node access check (metadata only)
---------------------------------

The Minikube node has /etc/kubernetes, /var/lib/etcd, /var/lib/kubelet,
/etc/cni/net.d, and /opt/cni/bin. The legacy /etc/kubernetes/pki directory is
absent, and `kubelet` is not found in the node's command path. These layout
differences mean some generic kube-bench file checks may not map directly to
this Minikube node.

Why the official Job was not launched
-------------------------------------

Aqua's official v0.16.0 job.yaml sets hostPID: true and mounts host directories
including /etc/kubernetes, /var/lib/etcd, /var/lib/kubelet, /usr/bin, and CNI
paths. The mounts are read-only and the manifest does not set privileged: true,
but the container would still be able to read sensitive control-plane
configuration, etcd data, and kubelet state, while also seeing host processes.
The host-path and host-PID exposure requires explicit approval; none was given.

Running the image directly with `docker run` against Docker Desktop would
inspect the Docker Desktop Linux environment, not the Minikube node's host
filesystem. It is therefore not a valid substitute for an in-cluster node
audit.

Safe next step
--------------

Do not downgrade or reconfigure the active cluster. Wait for an official
kube-bench image/profile that documents support for Kubernetes 1.37, then
review and obtain explicit approval for the read-only hostPath/hostPID access
before applying its node-scanning Job. A separate disposable cluster running
a Kubernetes version supported by the selected official image can provide a
valid benchmark for that separate cluster, but not for this current 1.37
cluster.
